Northwestern Formula Racing:
Dashboard

The Dashboard is the car's driver-facing display and vehicle interface. For Northwestern Formula Racing's 2026 build cycle, I laid out and brought up its controller board, a Raspberry Pi CM4 carrier, and wrote C++ and Python for it as one of a team of 7 on a ~25,000-line C++ codebase. I'm now designing the next revision.

C++ Embedded Software PCB Layout Altium Designer CAN Bus Python Git

1. Overview

The Project

Northwestern Formula Racing's Data Acquisition (DAQ) subteam builds the embedded systems behind the car's telemetry, driver interface, and real-time vehicle monitoring. The Dashboard is a subgroup within DAQ. I joined our team of 7 working on a codebase of roughly 25,000 lines of C++ (plus around 10,000 lines across other languages).

My work covers both hardware and software: layout and bring-up of the Dashboard's controller board, the C++ application that runs on it, and Python tooling the team uses during vehicle integration.

2. Hardware

Dashboard Controller PCB

The controller is a 4-layer carrier board for a Raspberry Pi CM4. I laid out two revisions (V2 and V3) in Altium Designer. The board carries the CM4, a CAN transceiver, USB 2.0, MIPI DSI video out to the driver display, and the driver I/O: addressable LEDs, buttons, and other inputs.

SubsystemDetails
PowerPower tree designed for 3 A nominal with input protection. Power traces and polygon pours sized for the load
CANTransceiver to the vehicle network, with the differential pair impedance-matched
DisplayMIPI DSI video output from the CM4 to the driver display
Driver I/OAddressable LED strips, buttons, and inputs, plus USB 2.0

I brought up both revisions from bare boards myself: hand soldering, checking each power rail, flashing firmware, and then integrating the board on the car.

3. Software

Firmware & Tooling

  • Wrote the C++ application that decodes vehicle CAN traffic and shows live sensor measurements on the driver display
  • Built a diagnostics page that surfaces inverter and system faults for analysis, used during bring-up and drive testing
  • Wrote Python tooling that generates dashboard signal viewers from the team's CAN DBC file. The team uses it as the source of truth for brake bias and sensor calibration during vehicle integration
  • Kept the dashboard's CAN handling in sync as the DBC definitions changed
